# ADR-006: NestJS 12 is ESM-only — Jest runs in ESM mode; Prisma 7 uses driver adapters

- **Status:** Accepted (Phase 0, verified locally)
- **Context:** NestJS 12 packages ship as ESM-only (`"type": "module"`).
  Jest 30 on Node 22 cannot `require()` them (native require(esm) support in
  Jest lands on Node ≥24.9). Prisma 7 removed the datasource `url` from
  `schema.prisma` and its client requires a driver adapter.
- **Decision:**
  - API tests run Jest in ESM mode:
    `ts-jest/presets/default-esm` + `extensionsToTreatAsEsm` +
    `NODE_OPTIONS=--experimental-vm-modules` (wired into the `test` script via
    cross-env so it works on Windows and CI).
  - `PrismaService` constructs the client with `@prisma/adapter-pg`
    (`new PrismaPg({ connectionString })`); the migrate/seed CLI gets its URL
    from `prisma.config.ts` (`env('DATABASE_URL')`).
  - The generated Prisma client lives at `apps/api/src/generated/prisma`
    (gitignored, regenerated by `pnpm db:generate` / the build script).
- **Consequences:** Works on Node 22 today and is forward-compatible (the flag
  can be dropped once we standardise on Node 24.9+). Local verification of the
  full chain (migrate → seed → boot → health) was done against the embedded
  dev Postgres (see README).
